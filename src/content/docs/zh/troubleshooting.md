按现象找对应的一节。这里只列有明确依据的处理方法；解决不了时，把现象和 Armadra 的版本（「设置 → 关于」）发到 [support@armadra.com](mailto:support@armadra.com)。

## CLI 显示「未安装」

现象：新建菜单里某个 Agent 旁标着「未安装」；或「设置 → Agent CLI」里状态为「需安装」，CLI 一行是「未检测到」。

1. Armadra 启动的是你机器上已经安装并登录的 CLI，它不替你安装或登录。先按该 CLI 自己的说明安装并登录一次。
2. 确认在终端里直接运行该命令能启动，并且它所在的目录在 `PATH` 中。
3. 回到「设置 → Agent CLI」查看状态是否变为已安装。
4. 如果项目放在 SSH 远程主机或服务器壳上，CLI 要装在那台机器上，并在那里登录。

会话视图所需的适配器可以在同一页安装，安装失败时的提示和处理是：

| 提示 | 处理 |
| --- | --- |
| 「没有找到 npm」 | 先安装 Node.js（含 npm） |
| 「npm 安装失败（退出码 …）」 | 点「查看输出」看原因，处理后「重试」 |
| 「安装超时，已停止」 | 检查网络后重试 |
| 「安装完成，但找不到程序，请检查 npm 全局目录是否在 PATH 中」 | 把 npm 的全局目录加进 `PATH` 后重试 |
| 「正在装另一项」 | 等当前安装结束 |

## Agent 无响应或状态不更新

1. **先区分是真的卡了，还是状态没传回来。** 节点头部的状态（运行中、需要你处理、已完成）来自 CLI 自己的回报，而回报通道只在从画布启动 CLI 时注入。在画布外的终端里单独启动的同一个 CLI，不会有状态。请在画布里新建节点启动它。
2. 打开「设置 → Agent CLI」，看该 CLI 是否显示「Hook 未生成」「技能未生成」「注入受限」或「待更新」。需要时点「重新生成注入」。
3. Agent 可能在等你：看节点头部有没有权限请求或提问，见下一节。
4. 节点可能处于节能休眠：空闲的 Agent 会先退出再结束进程，聚焦节点、收到投递或计划到点时会用 resume 接回原会话，稍等片刻。
5. 打开「资源」面板（⇧⌘U），找到这个会话，看进程是否占用异常；确认已无用时可以「结束会话」，再新建节点用 resume 接回。
6. 想及早发现卡住的 Agent，可以在「设置 → 通知」里打开「停滞提醒」。
7. 同一个 Agent 也可以在终端视图与会话视图之间切换，换一种视图再看。

## 权限请求不出现

1. 权限请求只在 CLI 的权限模式要求确认时才会产生。检查节点的权限模式，以及「设置 → 默认」里的「默认权限模式」：全自动类的模式不会询问。
2. 请求出现在节点头部，用「允许」「拒绝」「回答」直接处理；会话视图里则是权限卡。Armadra 不会替你回答。
3. 如果节点头部完全没有任何反馈，多半是上一节的原因：该 CLI 不是从画布启动的，或注入没有生成。按上一节检查并「重新生成注入」。
4. 离开窗口时想被叫回来，在「设置 → 通知」里打开「需要你时通知」。
5. 选了 CLI 不支持的权限模式时，启动前会明确报错，不会静默降级；换成它支持的模式即可。

## 远程连不上

手机或另一台电脑连不上桌面的对外服务、服务器壳或共享的主机时：

1. **局域网直连**：在「设置 → 远程访问」确认已打开「允许其他设备访问这台电脑」，并且监听地址不是「仅本机」。
2. **配对码过期**：配对码两分钟有效，过期后点「新配对码」，再用手机扫码。
3. **证书**：手机第一次连接要安装并信任本地 CA（页面里有 iOS 与 Android 的安装步骤）。装好后回到页面刷新。
4. **端口**：提示「端口已被占用」时，把「端口」改成「自动」或换一个；提示「没有权限使用这个端口」时换更高的端口。
5. **证书签发**：使用 ACME 时，「ACME 验证端口不可用」或「ACME 证书签发失败」通常是域名没有解析到这台机器，或外部 80 端口没有转发到验证端口。
6. **服务器壳**：页面能打开、登录后立刻掉线或返回 403，通常是地址栏里的地址与 `ARMADRA_PUBLIC_ORIGIN`（`--public-origin`）不一致，包括端口、大小写，或反向代理改了 `Host`。反向代理还需要放行 WebSocket，读超时放长。容器启动后立即退出，检查是否设置了 `ARMADRA_PUBLIC_ORIGIN`。
7. **主机状态**：「离线」表示对方没在线；「需要登录」时重新登录；「需要更新」或「这台主机的 Armadra 版本太旧」时，升级对方的 Armadra 再连；「版本不兼容，更新应用后重新打开」时更新本机应用。
8. 提示「访问权限已被收回」，说明共享已被撤销，需要对方重新授权或重新配对。

完整的证书、反向代理与排错表见[自托管部署与远程访问](/docs/server-and-devices/)以及 Armadra 仓库的[服务器部署指南](https://github.com/AMA-Link/Armadra/blob/main/docs/guides/server-deployment.md)。

## 更新失败

在「设置 → 关于」的「更新」区域，失败时会写明原因：

| 提示 | 处理 |
| --- | --- |
| 无法读取发布来源 | 检查网络后稍后重试；提示「可在 N 分钟后重试」时按时间重试 |
| 下载中断，已丢弃 | 点「重试」 |
| 磁盘空间不足，无法暂存安装包 | 腾出空间后重试 |
| 安装包的签名不是本机公钥签的，已拒绝；或下载到的字节与公布的摘要不一致，已丢弃 | 不要强行安装；重新检查更新，仍然如此时从发布页下载 |
| 本应用启动的后台服务没有停止，因此没有开始安装 | 退出 Armadra 后重新打开，再试一次 |
| 安装失败，当前版本没有被替换 | 当前版本可继续使用；从发布页手动安装新版本 |
| 更新已下载并通过校验，但当前安装未签名，不会安装 | 从发布页手动安装 |
| 更新未完成：… 没有报告新版本 | 从发布页手动安装，或回到上一版安装包 |

有些环境本来就不能原地更新：浏览器里的页面、后台服务在另一台机器上、Windows 便携版、Linux 的 deb 与 rpm。这时更新页会给出新安装包的下载。详见[设置、更新与数据](/docs/settings-and-updates/)。

## macOS 首次打开被拦

官方 macOS 安装包是 ad-hoc 签名、未经 Apple 公证，系统会在第一次打开时拦下它。

1. 把 `Armadra.app` 拖进「应用程序」，双击打开一次，系统提示无法验证并拦下。
2. 打开「系统设置 → 隐私与安全性」，滚到「安全性」，在 Armadra 的提示旁点「仍要打开」。
3. 输入登录密码或使用触控 ID 确认，再点「打开」。

macOS 15 起，「右键 → 打开」不再有效，必须走上面的「仍要打开」。不想点设置时，在终端执行：

```sh
xattr -dr com.apple.quarantine /Applications/Armadra.app
```

用 Homebrew 安装（`brew install --cask armadra`）不会去掉隔离标记，装完仍要确认一次，升级后同理。Windows 上，SmartScreen 提示时选择「仍要运行」。详见[安装](/docs/install/)。

## 其他常见情况

- **启动时报数据库损坏或版本过新**：Armadra 会拒绝启动，不会自动清库。从备份恢复，或换回能读取它的版本，步骤见[设置、更新与数据](/docs/settings-and-updates/)。
- **浏览器节点显示「服务端没有找到可用的 Chromium」**：在服务器上安装 Chromium，或用 `ARMADRA_BROWSER_PATH` 指定路径。
- **浏览器节点页面重新加载了**：隐藏时间超过设置的分钟数后页面会被回收以省内存，在「设置 → 浏览器」调整。
- **语言服务不工作**：编辑器状态里会写明原因，例如机器上没有对应的 language server、需要工作区的执行权限，或远端主机上没有语言服务。
- **「AI 生成」提交信息不可用**：需要机器上装有 Claude CLI，并为运行服务设置 `ANTHROPIC_API_KEY`；使用自定义服务地址时不可用。界面会写明具体原因。
- **代码托管面板提示没有凭据**：到「设置 → 代码托管」配置，见[Git 与 GitHub](/docs/git-and-github/)。
