一个目标要拆给几个 Agent 做时，可以交给协调者 `ama` 来分工；当某种协作方式稳定下来，再把它存成工作流模板反复运行。这一页讲这两件事怎么用。

## 协调者 ama

`ama` 是 Armadra 自带的协调 Agent，不需要另装。给它一个目标，它把子任务落成画布上的 Agent 节点、分派下去、等待并收齐结果。

1. 在画布上新建一个 ama 节点（新建菜单「AI 助手」分组里的「新建 Armadra Agent」，它就是 ama）。第一次使用先在「设置 → 凭据与密钥」填模型的 API Key，见[Agent 与 CLI](/docs/agents/)。
2. 在这个节点里说出目标，例如「把登录模块的测试补全，再让另一个 Agent 审查」。
3. ama 按需新建成员节点、连线、分派任务，并把汇总写进一张便签。

协调者本身只读代码、不动手改：要真正改文件，它只能交给画布上的成员。节点的「Agent 设置」里有「协调者」开关，只对能当协调者的 CLI 显示；节点运行中这个开关是灰的。

成员遇到权限请求时，ama 只报告「被阻塞」，不替你回答，见[权限请求与审批](/docs/approvals/)。

## 分派抽屉

ama 节点头部的「N 成员」打开右侧的「分派」抽屉。

- 「成员」页：每个成员任务的状态（运行中、需要你、已完成、本轮失败、已停止、空闲）与所处阶段（排队中、待回答、待验收、受阻、投递失败、失败）。点「打开」跳到成员节点；投递失败或失败的任务可以点「重试」。
- 汇总写进便签后，抽屉里有一行「汇总 → 便签「…」」，点开查看。任务对应的 PR 会出现「打开 PR #…」。
- 有新回复时显示「有新回复」；断线时显示「已断开，正在重连」。

## 团队编排

由 Agent 发起的编排支持几种形状：

- **并行**：多个成员同时做不同部分；
- **流水线**：上一个完成后下一个开始；
- **汇总**：多个成员的结果交给一个节点合并。

每个成员可以带一条自己的 Git worktree，互不干扰。

## 让 ama 按规则接单

ama 除了接你的话，还可以盯着一个仓库里没人认领的 Issue 或 PR，按你写好的规则接单。需要先在「设置 → 代码托管」连好该仓库所在平台的账号。

1. 在分派抽屉的「来源」页点「添加」，填「仓库」（形如 `github.com/owner/name`），选 Issue 或 PR，「协调者」选负责的 ama。
2. 新来源的「模式」是「观察」：只收集「候选」并由 ama 给出判定，不会起任何工作。
3. 在「候选」页逐条看：「判定」是 ama 的意见（接、跳过），你用「复核」点「同意」或「不同意」，用来评估它靠不靠谱。「统计」按「判定 · 同意 · 不同意」累计。
4. 看够之后，在来源里填「允许名单」（可以提需求的登录名，逗号分隔），点「规则」旁的「确认」确认仓库里的规则，再把「模式」改成「自动」。规则状态有「已确认」「已变更」「未确认」「缺失」。
5. 自动模式下，ama 只接名单内的人提的、规则没变过的候选，起成员后候选标为「已派发」。

规则文件一旦被改动，状态变成「已变更」，自动接单立刻停止，要你重新「确认」。「自动」需要允许名单和已确认的规则，否则设置不会生效。远端工作区读不到规则文件，只能用「观察」。ama 的判定只是意见，是否真的接单由 Armadra 按名单、规则和限流再核对一遍。来自外部的标题与正文一律当作资料，不当作指令。

## 工作流

当一种协作方式稳定下来，可以把它存成工作流模板：

1. 协调者交一份草案，弹出「工作流草案」卡片；
2. 填好「名称」，点「保存为工作流」确认成模板，或「丢弃」；
3. 之后在新建菜单「内容」分组的「工作流」里打开模板库，在「模板」页点「运行」，填参数起跑；也可以点「定时运行」交给自动化。

一份模板由「角色」（每个角色有名称和用哪个 CLI）、「步骤」与「参数」（可设「缺省值」）组成。步骤有三种：「提示」（把任务交给某个角色）、「汇总」（收齐其他步骤的产出）、「关卡」（停下等你确认）。点「编辑」可以改这些，步骤用「依赖」连成顺序，也可以拖动排序。

每次运行在画布上建一个 Frame 与各角色节点。运行中点「运行」页能看到每一步的状态（等待中、运行中、需要你、已完成、失败、已跳过、已停止）。遇到关卡时停在「需要你」，可以写「备注」后点「通过」或「拒绝」。运行可以「停止」，也可以勾选两次运行点「对比所选」，看哪些产出相同、哪些不同。

模板被改版后，仍按旧版本运行的定时计划会提示「模板已更新」，点「更新到最新版本」迁移；参数对不上时会告诉你缺哪些。

## 什么时候用工作流

开放任务的路径会随新发现变化，适合先在画布上和 ama 或几个 Agent 一起探索；步骤明确、需要反复执行的流程，再沉淀成工作流。两种方式可以结合。
